## Проверка новых гарантий

**Initial authority lease в Accept.** `engine.go:445` вызывает final deadlineGate после validateInputs и reauthorize, перед persistAcceptance. Список deadlines теперь включает и proposal effective deadline, и **decision.ExpiresAt исходного отдельного review**. Reauthorize продолжает проверять actor/policy/scope/capability, но renewal не подменяет уже выбранную bound expiry. Это согласуется с MEM-002 Acceptance identity и original требованием versioned host decisions, проверяемых заново перед commit/return. Zero expiry остаётся явно unbounded host decision; arbitrary cross-system atomicity не заявлена.

`lease_lineage_regression_test.go:24` на memory и SQLite использует renewingAuthority, затем source callback переводит clock ровно на начальную expiry. Renewed same-actor/same-policy decision имеет новый deadline; gate всё равно возвращает ErrStaleInput, empty Acceptance и сохраняет Proposal.State=Proposed. После отключения advancing callback новое отдельное review получает свежую lease, Accept+Commit успешно завершаются. Проверяются state и receipt, а не только error string.

**Prospective mandatory transitive lineage.** `commit_state.go:57` вызывает commitDeadlineGate с target RecordID после staged reconcile и всех финальных host calls, перед persistCommit. `deadline_gate.go:21` traverses exact scoped active heads и проверяет forbiddenRecord **на каждом ребре**, включая глубоко транзитивные inputs. Если target встретился anywhere, ErrInvalid. Рекурсивные/непосредственные identity обходы не допускаются; проверка bounded maximumLineageRecords, source head identity/revision/state и effective expiry сохранена. `deadline_gate.go:72` затем делает один final clock sample через checkDeadlines (`:52`); read/deadline paths без prospective target по-прежнему используют тот же helper без forbiddenRecord.

Это проверка жизнеспособности будущего состояния при live exact-head semantics: обновление a1→a2 не может одновременно создать a2, обязательный input которого b1 сам требует ещё актуальный a1. Исторический revision DAG не объявляется циклическим. Safe independent ancestor update остаётся разрешён и инвалидирует старые dependents по существующему контракту; допустимый Append/Supersede не сужен произвольным запретом ancestry.

`lease_lineage_regression_test.go:63` на обоих stores × Append/Supersede строит b1→a1, затем candidate a2→b1. Direct self check недостаточен; commit отклоняется ErrInvalid и empty canonical receipt. Assertions проверяют **a/b/c head revision=1, Active и исходный payload**, включая независимый c1, который при Supersede уже staged для mutation. Atomic rollback сохраняет его. Затем тот же unconsumed operation ID с другим safe target успешно commits, repeat returns identical receipt и canonical Get читает revision1/updated payload. Это подтверждает transactional rejection, полноту mandatory lineage и idempotency после rejected attempt.
